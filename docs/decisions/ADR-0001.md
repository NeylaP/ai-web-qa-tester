# ADR-0001: Day 1 Workspace Setup — Version Matrix and Tooling Decisions

**Date**: 2026-07-12
**Status**: Accepted

## Context

Day 1 bootstrapping of the `ai-web-qa-tester` Nx monorepo. All decisions here are the result of running the compatibility spike or observing generator behavior on Nx v21.6.11.

## Decision 1: Nx Version

**Choice**: `21.6.11` (exact pin)
**Rationale**: Nx breaks between minor versions. Exact pin ensures reproducible installs across environments.

**Validated environment**:
- Node.js: v24.15.0
- npm: bundled with Node 24
- OS: Windows 11 Pro 10.0.26200

## Decision 2: Workspace Preset

**Choice**: `--preset=apps`
**Original design**: `--preset=empty`
**Reason for change**: `--preset=empty` was removed in Nx v21. `create-nx-workspace@21.6.11` errors with "The 'empty' package does not support Nx generators." `--preset=apps` is the minimal equivalent.

**Side effect**: Projects scaffold at root level (`api/`, `web/`, `cli/`, `core-domain/`, `core-application/`) instead of under `apps/` and `libs/` subdirectories. This is the Nx v21 `--preset=apps` default behavior and does not affect functionality or boundary enforcement.

## Decision 3: Angular Test Runner

**Choice**: Vitest via `@nx/angular:application --unitTestRunner=vitest`
**Angular version installed**: 20.3.26
**`@analogjs/vitest-angular` version**: 1.19.4

**Required fix — `pool: 'forks'`**: Angular 20 + zone.js does not work with Vitest's default thread pool (`threads`). Must set `pool: 'forks'` in `web/vite.config.mts`. Without this, `getTestBed().initTestEnvironment()` throws `NG0401: No platform exists!`.

## Decision 4: NestJS and Node Test Runner

**Choice**: Vitest wired manually (`--unitTestRunner=none` + manual `vite.config.ts`)
**Reason**: `@nx/nest:application` and `@nx/node:application` in Nx v21 only support `--unitTestRunner=jest|none`. Vitest was wired manually by creating `vite.config.ts` and `tsconfig.spec.json` in each project, following the same pattern as `@nx/js:library`.

## Decision 5: Test Target Registration

**Discovery**: Nx v21 infers test targets from `vite.config.ts` as `vite:test`, NOT as `test`. `nx run-many -t test` will not pick up inferred targets — only explicitly declared ones.

**Fix applied**: Added explicit `test` target with `executor: "@nx/vite:test"` to `api/project.json`, `cli/project.json`, `core-domain/project.json`, and `core-application/project.json`.

## Decision 6: Module Boundary Enforcement

**Rule**: `@nx/enforce-module-boundaries` in root `eslint.config.mjs`.
**Constraints**:
- `type:domain` → no deps on any tagged lib
- `type:application` → may only depend on `type:domain`
- `type:app` → may depend on `type:domain` and `type:application`

**Verification**: Temporarily imported `@ai-web-qa-tester/core-application` inside `core-domain`. Lint exited non-zero with `@nx/enforce-module-boundaries` error. The original design called for testing with `@nestjs/common` — this does NOT trigger the rule (external packages are out of scope for module boundary enforcement).

## Consequence

All 5 projects (`api`, `web`, `cli`, `core-domain`, `core-application`) build, lint, and test successfully with a single runner (Vitest) across the entire monorepo.
